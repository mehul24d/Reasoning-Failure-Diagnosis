## What S2 decides

S2 is data production, not a research question. It fixes everything that later experiments
(E1–E4) take as given: which problems, which prompts, how traces are generated and scored, and
how steps, gold variables, error types and the first error step s0 are derived. It has
acceptance criteria (below) but no hypothesis.

## Data

### Primary population (preferred)
GSM-Symbolic templates with no-op distractor clauses, as recreated by Qu and Gomes. Failure set
= problems solved without the distractor and failed with it (plan 3.12.3). Not public as of
2026-11-12.

### Fallback population (used if the no-op data are not available when the 9B run starts)
* `apple/GSM-Symbolic`, config `main`: 100 templates, 50 instances each, test split.
* Instances: the first **8 per template** by instance number (`harness/datasets.py
  --instances 8`), giving **800 problems**.
* Failure set: **natural failures** (plan 3.12.3, second population): every problem whose
  greedy trace is scored wrong. Each failure keeps the solved instances of the same template as
  its reference set.
* P1 and P2 configs: not part of S2. They may be added later as an exploratory generalisation
  set, pre-registered separately.

**Expected size (fallback).** 800 problems × 2 styles × 3 paraphrases = 4,800 greedy traces per
model. At 80% accuracy this gives about 960 failed traces, about 384 of them in the 40 test
templates, above the plan's minimum of 320 test failures from at least 40 templates. If fewer
than 320 test failures are observed, instances 9–16 of every template are added (same rules)
before any probe is trained, and this is reported.

### Template split
* By template, never by problem: 40 train / 20 dev / 40 test, from `harness/splits.py` with
  **seed 0** over the sorted template ids.
* The split file `data/splits/gsm_symbolic_main_seed0.json` is generated once and committed
  with this file. Later steps read it and never recompute it.

### What is not touched
GSM8K test and MATH-500 are not used in S2. No GSM-Symbolic trace has been generated by any model
in this project before this file is committed (M0 used GSM8K train only).

## Generation

* **Greedy:** temperature 0, `do_sample=False`, repetition penalty 1.0 (explicitly set, never
  inherited), no top-p or top-k, batch size 1. Checked by `is_pure_greedy` before every run.
* **Prompts:** both styles (`marked`, `terse`) × paraphrases 0, 1, 2, wrapped in each model's own
  chat template, exactly one BOS token (asserted).
* **max_new_tokens: 1024** (was 512, provisional). Reason: on Gemma-2-2B-IT, 0.4% of traces hit
  512 and the median length was 134–144 tokens; larger models write longer solutions, and greedy
  decoding stops at the end-of-turn token, so the larger limit only costs time on the rare long
  traces. E0 fixes 512 for its own traces, including the 9B E0 run in S1, so
  `configs/experiment.yaml` is changed to 1024 only after S1 on 9B is finished, in the commit
  that makes this file binding.
* **Resume:** a run that stops is resumed from its output file; a trace is never regenerated.
* **Provenance:** for every trace file, the sha256, line count, code commit and run identifier
  are written to `reports/m1/<model>_traces_provenance.txt`.

The sampled subset (T = 0.7, k = 5, stable vs borderline failures) belongs to S3 and is
pre-registered with E1–E2.

## Scoring

* `parsing/answers.py` (sha256 `9c857958…`): the last number after the last answer marker, on
  that marker's line, normalised for `$`, commas, spaces and a trailing period. No marker → no
  answer → scored wrong. No fallback to the last number in the text.
* Correct = the extracted answer equals the gold answer exactly (as fractions).
* A random sample of 40 extractions per model is checked by hand and reported.

## Parsing, gold programs and s0

* **Parser frozen at v4** (commit `e559c46`). sha256 at drafting time:
  `expr.py b29fd48b…`, `steps.py 1fe40471…`, `gold.py 5f956924…`, `answers.py 9c857958…`.
  The rules are listed in `reports/m0/parsing_manual_check_v4.md`.
* **Gold program:** from each GSM-Symbolic solution (`parsing/gold.py`, source
  `gsm_symbolic`). Problems whose gold program is not `ok` are excluded from every step-level
  analysis and counted in the coverage report.
* **Error types:** Algorithm 1 order of precedence (planning, binding, arithmetic, none), with
  the v4 rules: alignment tiers 1–3 consume a gold step, references resolve through tier 4, a step
  that correctly reuses an earlier wrong value is not a new error.
* **Primary s0 = lenient s0:** the first step with an error, skipping steps marked
  `extra_valid` (valid alternative derivations). **Strict s0** (every unmatched step counts, as
  Algorithm 1 is written) is reported alongside as a secondary label. Reason: on the M0 traces,
  strict s0 flagged about 20% of correct traces against 5% for lenient, while both agreed on
  failed traces (81–92%).
* **Ambiguous operand matches** (equal values in several slots) are flagged and excluded from
  the operand variable, but kept for the other variables (plan 3.12.4).
* **Failures without s0** (no computational step, stopped early, answer extraction differs) are
  kept in the failure counts but excluded from step-level variable sets, and are reported by
  cause.

## Acceptance criteria (checked on the 9B traces before E1 starts)

| Check | Criterion | If not met |
|---|---|---|
| Traces with an extracted answer | ≥ 97% | inspect formats; fix scoring only for a new marker form, as a dated deviation |
| Traces hitting max_new_tokens | ≤ 1% | report; such traces stay scored wrong and are excluded from failure sets |
| Gold program ok (GSM-Symbolic main) | ≥ 80% of problems | report; excluded problems listed |
| False error steps on correct traces (lenient s0) | ≤ 10% | parser fix before E1, as a dated deviation |
| Hand check of 40 random parsed steps (fresh seed) | ≥ 36 / 40 correct | parser fix before E1, as a dated deviation, then a new 40-step check |
| Test failures with s0 | ≥ 320 from ≥ 40 templates | add instances 9–16 (see Data) |

The hand check uses the M0 standard: a step is correct only if operation, operands, result,
aligned gold step and error type are all right. A second group member re-checks 10 of the 40
steps independently, and agreement is reported.

## Exact commands (fallback population; run from the repository root)

```bash
python -m harness.datasets --source gsm_symbolic --config main --instances 8 \
  --out data/s2_gsms_main_i8.jsonl
python -m harness.splits --problems data/s2_gsms_main_i8.jsonl --seed 0 \
  --out data/splits/gsm_symbolic_main_seed0.json
python -m harness.generate --model gemma-2-9b-it --problems data/s2_gsms_main_i8.jsonl \
  --out data/generated/gemma-2-9b-it/s2_traces.jsonl --mode greedy
python -m harness.score --traces data/generated/gemma-2-9b-it/s2_traces.jsonl \
  --out data/generated/gemma-2-9b-it/s2_traces_scored.jsonl
python scripts/validate_parsing.py --traces data/generated/gemma-2-9b-it/s2_traces_scored.jsonl \
  --problems data/s2_gsms_main_i8.jsonl --label s2_traces \
  --out reports/m1/parse_coverage_gemma-2-9b-it.json \
  --sample-out reports/m1/parsing_sample_gemma-2-9b-it.md --seed 4
```
