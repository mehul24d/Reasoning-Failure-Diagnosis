# Pre-registration: R1 — redesigned pilot of the repair test (train and dev templates)

**Status: committed before any R1 data exist** (no calibration run, no edited continuation, no
stability sample of a train or dev failure). The population counts below come from the parser
labels only. Written on the user's instruction of 2026-11-26 (DECISIONS D48).

* **Date committed:** 2026-11-26
* **What it is:** a development pilot of the Semester VIII repair test (plan E10, the
  self-sourced repair method), run now on Gemma-2-2B-IT to find out whether the test can show
  anything at all. It is **not** one of the minor project's confirmatory experiments (E1–E4 only
  read the model), and it uses **no test template**. Every number is a development result:
  - the labels are automatic (parser v4), and the S5 annotator agreement is still pending;
  - dev items are used both to calibrate the strength and in the pilot (below).
* **Replaces** the October pilot's repair test (`docs/prereg/pilot.md` §3.4), which changed 0 of 22
  items at the pre-registered strengths {1, 2, 4, 8}× (single-token edit). Repeating it larger
  would show nothing, so the edit and its strength are redesigned first, as in
  `docs/BASELINE_REPORT.md` §4.

## Question and hypotheses

Do edits that write the correct value of a content variable into the step where the model went
wrong repair distractor failures more than norm-matched random edits do, and more than an edit
along an evaluation ("this step is correct") direction?

These are the project's hypotheses, not claims:
- **H1.** Oracle content edits give a net gain above the random null (p ≤ 0.05) and ≥ 5 points.
- **H2.** Self-sourced edits give a net gain above the random null, with less damage than
  evaluation edits.
- **H3.** Evaluation edits are not distinguishable from random edits.

**Stop rule (fixed now).** If calibration finds no strength at which the oracle edit changes
outputs before outputs break (below), the pilot is **not** scaled up. The finding is then the
calibration curve, reported as it is.

## Population and items (train 33 + dev 16 templates; S2 greedy traces)

- **Failures:** primary distractor failures (A14: the distractor-condition trace is wrong and its
  clean twin, same instance and prompt, is right), with a gold program, not stopped at 512
  tokens, with a lenient first error step s0 (parser v4), and **content-attributable at s0**: the
  distractor quantity is an operand of s0, or s0's operation differs from the gold operation.
  From the labels: **107 failures** (66 train, 41 dev) on 24 templates.
- **Variable per failure:** `content/binary` (distractor used) if the distractor is an operand at
  s0, otherwise `content/4-class` (operation + − × ÷). Bound value = the model's own value at s0;
  gold value = "not used" or the gold operation.
- **Matched solved set (damage):** one solved distractor-condition trace per failure, from the
  same template, drawn without replacement (seed 20261126). If the template's pool is used up,
  drawn with replacement; if the template has no solved trace, drawn from the solved traces of the
  other templates of the same split. Fallback counts are reported. Its edit step is the
  candidate step (a step with the variable's label defined) at the same rank as the failure's s0
  among its own candidate steps, clipped to the last one. For solved items gold = bound.
- **Stability:** k = 5 samples at T = 0.7 per failure, S3 settings and seeding
  (`harness.batched.batch_seed`). A failure is *stable* if 0 of 5 samples are correct, and
  *borderline* otherwise. These are new samples: S3 sampled test failures only (A5).

## Directions (CPU, `repair/build_inputs.py`; train templates only)

- Read at the step's first token (`step_first`), from the S4 residual cache.
- **Layer and λ per content variable:** the shared construction procedure of `prereg/E1.md`
  (`probes/fit.py`), on all train rows of the variable: template-grouped 5-fold CV, layer chosen
  at λ = 1 over blocks 0–25, then λ from the grid 10^{−4..2} at that layer.
- **Cross-fitting:** a train item uses class means and probe fitted on the train templates
  outside its own CV fold; a dev item uses all train templates.
- Edits, all at the item's variable layer L_v and in raw residual space:

| Condition | Edit |
|---|---|
| oracle content | μ_v[gold] − μ_v[bound] (zero on solved items) |
| self-sourced | if the probe's top-1 at s0 (decoded) ≠ bound: μ_v[decoded] − μ_v[bound]; otherwise no edit |
| evaluation | μ[step correct] − μ[step incorrect], step-correctness labels, at the same layer L_v |
| random null | 100 Gaussian directions, seed 20261126, the same 100 for every item |

- **Norm matching:** every non-zero edit is rescaled to norm m × r_v, where r_v is the mean
  distance between the class means of the item's variable at L_v (all train rows). A zero edit is
  not run: the outcome is the recorded trace.

## The edit (`repair/engine.py`)

- **Site:** added to the output of block L_v at **every token of the first deviating step**:
  absolute positions from s0's first token up to (not including) the first token of the next step
  (or the step's last token + 1 for the last step). The window is fixed in absolute positions, so
  it is the same in the teacher-forced replay and in a regenerated continuation.
- **Replay:** the model's own recorded trace up to the edit, then greedy decoding under the edit:
  float32, eager attention, the S2 stop rule (end of the answer line or end of turn), at most 512
  generated tokens from the end of the prompt.
- **Exact divergence shortcut:** one teacher-forced pass per edit over the recorded tokens, with
  an unedited reference row in every batch. Only edits whose argmax differs from the reference
  are regenerated, from the first differing position. Exactness against brute-force edited
  generation is tested (`tests/test_repair_engine.py`).
- **Outcomes per run:** final answer (S2 extraction rule), correct, *answer changed* (the final
  answer differs from the recorded one), *broken* (no extractable answer, or the 512-token cap).

## Calibration of the strength (dev items only)

Grid m ∈ {0.25, 0.5, 1, 2, 4, 8, 16}.
1. The oracle edit on the 41 dev failures at every m on the grid.
2. **m\*** = the smallest m at which the oracle edit changes the final answer of **≥ 20%** of the
   dev failures while **≤ 10%** of them are broken. Climbing stops at the first m whose oracle
   break rate is > 10%: outputs break before they change.
3. If m\* exists: self-sourced, evaluation and 10 random directions (the first 10 of the 100) on
   all dev items (failures and solved) at m\* and at m\*/2. This answers "what do random
   directions do at the same strength". If there is no m\*: the 10 random directions on the dev
   failures at every m, for the curve. **Then the pilot stops (stop rule).**
4. Calibration uses only "answer changed" and "broken", never correctness.

## The pilot at m\* (train + dev items)

- All 214 items (107 failures, 107 solved), conditions oracle, self-sourced, evaluation and the
  100 random directions, at m\*. Dev rows at m\* that calibration already produced are reused,
  not recomputed (the runs are deterministic).
- **Metrics:** repair = share of failures made correct; damage = share of solved items made
  wrong; net gain = accuracy change over failures + solved. 95% template-clustered bootstrap CIs
  (10,000 resamples). The random null gives one net gain per direction, and
  p = (1 + #{random net ≥ condition net}) / 101. The difference from the random mean also gets a
  template-clustered CI. Changed-answer and broken rates are reported for every condition.
- **Reported for:** all items (headline); train only (not used for calibration); dev only;
  binary vs 4-class items; stable vs borderline failures (each with the solved items matched to
  them). Gate open rates of the self-sourced edit, on failures and on solved items.
- **Words** (as in `docs/prereg/pilot.md`): *supported* only if the net CI excludes 0,
  p ≤ 0.05 against the random null and the estimate is ≥ 5 points; *not supported* if the net CI's
  upper end is below 5 points; otherwise *inconclusive*. Never "significant". Every result
  states n, templates and the clustering (A16).

## Budget and compute

- Kaggle 2 × T4 ($0), one session, both GPUs (one worker each). T4-hours = 2 × session hours,
  setup included. **Cap: 8 T4-hours** for all GPU work of the 2026-11-26 request.
- Order in the session: stability samples, then calibration, then the projection, then the pilot.
- **Projection:** from the measured calibration timings and the divergence rates at m\* (the
  random rate for the 100 random directions). If T4-hours used + 1.25 × projected > 8, the pilot
  is **not started** and the projection is reported. A hard stop at 8 T4-hours ends any stage
  cleanly; partial results are reported as partial.

## Deviations from the October pilot (`docs/prereg/pilot.md`), with reasons

1. **Train and dev templates only**: the test templates stay locked (user's rule).
2. **Edit over the whole first deviating step**, not its first token: single-token edits changed
   nothing at 1–8× and needed 64× (D20).
3. **Strength by dev calibration** (change rate and break rate), not by train net gain over
   {1, 2, 4, 8}.
4. **Every condition at the content variable's layer**, the evaluation direction included, so
   that the norms are comparable (the October pilot used the evaluation variable's own layer).
5. **No oracle residual patch:** not requested, and the clean twin's step has other positions and
   length, so a whole-step patch is not defined without new choices.
6. **Layer and λ by the E1 procedure** (λ grid) instead of C = 0.1.
7. **Matched solved set with fallbacks**, so there is one solved item per failure (D47).
8. **Population:** the main study's primary distractor failures (S2, 8 instances per template,
   reviewed clauses), not the October run's 776 traces.
